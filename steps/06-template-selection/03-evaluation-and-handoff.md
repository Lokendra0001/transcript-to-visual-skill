# Evaluation, adaptation, and handoff

Evaluate every profiled candidate against each visual unit qualitatively. Explain structural fit, required relationship representation, hierarchy, density, assets, reading order, guidelines, orientation, readability risk, and adaptation effort. A visually appealing candidate remains ineligible when a mandatory requirement cannot be represented without changing meaning.

Select one coherent primary reference per visual unit unless a compatible supporting component is necessary and allowed. Derive component patterns from observed reference evidence, plan adaptations explicitly, and map required upstream elements to representation strategies. Leave content unchanged; if variants are insufficient, create an adaptation requirement.

Create an actionable design direction for Step 08: retained/adaptable characteristics, background/color principles, hierarchy, containers, logo/icon handling, connectors, grouping, spacing, and brand constraints. It must not contain coordinates, SVG, or rendered output. Run `validate_selection.py`; report unexecuted semantic checks honestly and hand off the final selection plus validation report to Steps 07–08.

Include actionable guidance on observed text density, visual-to-text balance, component variety, whitespace, visual grouping and minimal explanations. Adapt these characteristics to the content and user preferences rather than hardcoding a reference layout. Preserve explicit approved layout locks.
