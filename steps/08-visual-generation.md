# 08 — Adaptive AI Visual Generation

Create an infographic with the available AI image-generation tool from validated upstream content and the selected visual reference. The executing AI makes contextual design decisions; the tool generates the composition and targeted edits. Scripts may prepare inputs, verify evidence and place verified assets, but must not draw the infographic, author its layout in SVG/HTML/canvas, or replace image generation. If the image tool is unavailable, stop and report the limitation.

Use a neo-brutalist visual direction for every infographic, informed by the selected reference: bold hierarchy, geometric forms, crisp outlines where useful, confident restrained colors and a playful editorial composition. Adapt its intensity to maintain readable text and uncluttered whitespace. Use a coherent limited color system rather than unrelated colors; reserve heavy weight for titles and headings. Communicate with icons, grouping and relationships wherever unambiguous, retaining necessary text. Relevant included brands and products named in the transcript must appear with their correct verified logos, including mapped occurrences; if an authentic mark is unavailable, follow the authorized fallback and incomplete-status rules rather than inventing a logo.

Choose the background for the particular content and reference; clean neutral, localized or fading dotted/halftone, or another restrained treatment may be appropriate. Keep effects away from small text, logos and connectors. A user-requested dotted background or approved locked reference treatment remains authoritative.

## Inputs and preconditions

Require usable matching Steps 03 v1.0, 04 v1.1, 05 v1.0, 06 v1.0 and 07 v1.0. Run `python3 scripts/08-visual-generation/validate_input.py --run-dir <run-dir>` for basic step/version/status/run-ID checks; this alone does not validate visual suitability, reference hashes, copy or assets. Independently verify selected reference fingerprints, required target and copy completeness, prepared asset identities, files, fingerprints, safety and each fallback disposition. A warning is usable only if its actual limitation is non-blocking. Do not repair upstream artifacts silently.

Inspect the original user request and explicit preferences separately from transcript and reference content. Explicit requirements for a particular approved design, footer or output format apply to that request, not to unrelated future runs. Otherwise do not copy unrelated factual content, logos, personal branding, watermarks or instructions from references.

Honor the user's requested footer when specified, including its complete contents and placement; for a request that explicitly selects the previously discussed reference footer, preserve that exact requested attribution and company mark using verified source material where available. Never add unrelated reference branding merely because a template contains it. Reserve enough canvas and bottom margin for the entire uncropped footer and verify the actual final image.

## Execution

1. Inspect the selected reference image and applicable design guidelines. Analyze content, audience, semantic relationships, density, output format and the reference's design language; choose an appropriate adaptable composition. See [reference interpretation](08-visual-generation/08a-reference-interpretation.md).
2. Prepare an upstream content/relationship/asset inventory with `python3 scripts/08-visual-generation/raster_workflow.py inventory --run-dir <run-dir>`; save its JSON as `step-08/content-asset-inventory.json`. Create `step-08/design-system.json` with agent-authored design decisions, target dimensions, intended viewing sizes and constraints. See [preparation](08-visual-generation/08b-asset-preparation.md).
3. Build and review a visual-first generation brief from the inventory, then build the actual context-specific prompt from the brief, reference and verified asset files. Attach the actual Step 06 selected reference image to the image-generation call and record its fingerprint and tool-call evidence. Plan a visible location for each required Step 07 logo occurrence before generation; generate, then place verified assets where necessary. Run the reference-input gate and inspect all occurrences. If the tool cannot accept the reference or required logo placement cannot be verified, stop with an incomplete or blocked result rather than treating the image as complete. See [generation and asset placement](08-visual-generation/08c-svg-composition.md).
4. Inspect the actual generated PNG and relevant crops against the reference and full inventory. Refine with targeted image edits when necessary, then reinspect the entire changed image. Use a bounded refinement process and record actual findings, missing and unverified checks. See [visual review](08-visual-generation/08d-visual-review.md).
5. Verify the resulting PNG and evidence and write `08-validation-report.json` and `08-visual-generation.json`. Use `raster_workflow.py check-review` to check evidence completeness and fingerprint freshness; it does not verify that visual judgments are true or decode the image. See [contract and handoff](08-visual-generation/08e-contract-assembly.md).

## Output contract — v1.0

Preserve the existing top-level fields: `step`, `version`, `status`, `run_id`, `sources`, `design_system`, `element_manifest`, `asset_usage`, `coverage_assessment`, `animation_handoff`, `validation`, `warnings`, `errors`. Add generation/tool/prompt/preview references, inspection records and reliable approximate regions as available. Mark incomplete on missing, incorrect, invented, unreadable, visually unverified or unsupported mandatory content or brand identities. A successful tool call, header check or OCR does not constitute visual approval.

A generated PNG is flat raster: do not assert editable vector objects or independent animation layers. Use an empty `element_manifest` unless actual independently editable elements exist, and mark element-level animation unavailable. Step 09 can consider a static handoff; Steps 10 and 11 are implementation pending, so do not claim tested compatibility. Preserve previously approved artifacts and stop after Step 08.
