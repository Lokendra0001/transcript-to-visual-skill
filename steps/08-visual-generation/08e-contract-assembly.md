# 08e — Verification and Handoff

Verify that the PNG fully decodes using an available image library or viewer; record actual dimensions and hash. Run `python3 scripts/08-visual-generation/raster_workflow.py check-review --image <png> --review <visual-review.json> --inventory <content-asset-inventory.json>`. This checks PNG header, dimensions, hash, required IDs and completeness of agent-authored evidence only; it does not decode all pixels, check semantic truth, inspect a logo or prove visual approval. An unavailable decode or visual review must be reported, not inferred as passing.

Also run `raster_workflow.py check-reference --reference <selected-reference> --record <reference-input.json>` and independently confirm that the selected path/hash matches Step 06 and the recorded tool call actually attached that file. Require a passing, image-specific per-occurrence review for each required mapped logo and a visual comparison with the selected reference. The helper checks records and hashes only; it cannot verify remote tool inputs or visual resemblance. An unexecuted, missing, stale or failed gate makes the output incomplete or blocked, even if a PNG exists.

Create `08-validation-report.json` with separate deterministic, actual visual review and unresolved or unsupported checks. Never declare a pass for a failed or unperformed check. The PNG is flat: retain `element_manifest: []` and mark element-level animation unavailable. Describe observed component regions and relationships separately without asserting SVG editability or invented layers. Write the Step 08 v1.0 contract from the main instructions, with generation references, coverage, provenance, warnings and limitations. Mark success only when every required gate really passes; otherwise use `incomplete` or `blocked` and show the image as a draft. Step 09 can consume an explicitly static handoff but cannot animate independent PNG objects; Steps 10–11 have no implemented contracts yet.
